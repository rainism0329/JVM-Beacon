# 现有功能审查：0.14.0 → 0.14.1

日期：2026-09-28。审查起点为 `e4082f4` 的 0.14.0，工作区起始无未提交修改；先观察当前界面，再按连接/执行、数据证据、JFR 三条路径检查实现和现有测试。修复范围是可靠性，未增加新的分析菜单。最终包运行结果见 [validation](validation.md) 与 [GUI 记录](gui-validation.md)。

## 工作流观察

本轮使用 Windows / IC 2025.1.3 / JBR 21，1388×974、125%、Light；独立 Corretto 21.0.9 fixture，无业务进程。以下 baseline 截图为 **修复前 0.14.0**，不能作为新包通过证据。

1. **进入与连接：基本正常，发现效率仍可改进。** [未连接页](../build/reports/audit-0.14.1/baseline-welcome.png)给出连接与打开现场入口；手输自有 PID、明确允许管理代理后真实连接成功。本地列表含 IDE/Gradle 等候选，尚无 Run/Debug 精确关联，进程多时辨认成本高。
2. **指标与趋势：本轮正常。** 开启自动采样后从 2 点增长至 10 点，[真实曲线](../build/reports/audit-0.14.1/baseline-trend.png)反映 heap 变化，初始暂停空档未错误连线。该观察不证明用户此前所有间歇失败已排除。自有定时目标退出后显示 Stale 及 CONNECTION 原因。
3. **MBean 浏览：能用，但阅读空间不足。** 搜索并选中真实 Probe，[详情页](../build/reports/audit-0.14.1/baseline-mbean.png)在当前尺寸仅直接看到少量属性/操作，说明和结果区偏挤。更关键的是元数据与全部 getter 批量读取绑定，慢 getter 会拖住整个对象；这是后续优先改进项。
4. **受控操作：发现确定性反馈与并发问题，已修。** 开 Auto，在 `fail()` 确认框停留再执行，出现 [pending 与“已有请求”同时显示](../build/reports/audit-0.14.1/baseline-pending.png)。这是模态循环期间自动采样抢占请求的真实复现，不是方法已经执行的证据。代码还确认失败回调未更新结果、自动成功采样覆盖用户提示。
5. **线程、现场与 JFR：最终主流程正常，验收边界仍保留。** 最终 GUI 采集 16 条平台线程、保存并新页重开 82 样本与备注、下载解析 30 秒 JFR，关闭连接后确认自有录制释放；[逐步截图](gui-validation.md)另列。完整键盘、屏幕阅读器、多缩放组合仍未验收，自动回归不能替代这些实操。

## 修复与证据

| 问题 | 影响及 0.14.1 处理 | 证据类型 |
|---|---|---|
| 目标 getter 异常误当权限/TLS/连接错误 | 优先识别 JMX 目标异常包装，包括 RuntimeErrorException，避免误断健康连接 | 自有真实 JVM 抛错、继续读取的集成回归 |
| 模态确认期间自动请求竞争、操作失败一直 pending | 统一确认门控，恢复原采样选择；忙时明确不提交，只在准入后 pending；失败/停止等待结束 pending；正常自动采样保留用户反馈 | 修复前 GUI 复现、Swing 嵌套事件循环测试及最终 GUI |
| 快照比较对未知身份、计数回退/时窗错误计算差值 | 复用完整身份与 Timeline 证据规则，保留精确数值；ThreadComparison 使用同一身份边界 | 核心回归；不是根因诊断 |
| TabularData 长字段名截断后错列/丢值 | 对受限/失败/重名字段禁用 Rows 并解释，Structure 保留已有节点 | 真实 TabularData 构造与组件回归 |
| 属性追踪时钟倒退造成 UI 异常 | 保留原始时窗、丢弃无效数值、记录缺口并沿既有失败路径暂停 | 核心回归 |
| JFR 本地普通 IOException 被当网络失败 | 本地文件异常独立归为 FILE，保留连接与录制；远程流异常仍保留原类别 | 自有认证 fixture 注入写入/关闭/远程读取失败及清理回归 |
| 新 JFR 文件沿用旧高亮、内存表逐行更新 | 新文件清高亮，范围更新保留；表格整批替换，排序详情正确 | 组件测试，4096 GC/2048 allocation 上限模型 |

复杂 Rows 的保守规则也会禁用仅值被截断的行表；这避免把受限节点冒充完整字段，暂未拆分名称和数值的截断标记。批量表格更新是减少 EDT 工作：独立 Swing 2048 行旧路径观察为 10.9–32.7 ms，**未证实秒级冻结**，不把优化写成修复已发生卡死。

## 后续优先级

1. **MBean 元数据先显示、属性按需读取。** 先展示操作签名和属性定义，单属性读取/刷新有独立时窗和失败；重整主从布局与结果区域。直接减少慢 getter 对日常入口的阻塞，优先于堆叠新分析页。
2. **Run/Debug 目标关联。** 精确使用所启动进程的 PID/启动证据并处理退出重启；不能按名称猜连未知目标。减少查找 PID 的步骤。
3. **可靠性专项。** 最大 JFR/8 标签/项目关闭的 IDE 内存和 EDT 观察；PasswordSafe 输入/结果统一可清除所有权，覆盖未开始和容量拒绝路径。目前发现未启动保存任务的 char[] 缺少显式擦除，尚无日志/磁盘外泄证据；IU GUI、更多 JDK/OS 和无障碍矩阵仍需补齐。
4. **保存完整诊断上下文。** 设计包含文件引用/校验、已应用范围、备注、Hot threads/Watch 的工作空间记录，明确缺失和脱敏边界；现有 `.jvmb` 不能恢复这些未保存内容。
5. **再扩展高级分析。** VirtualThreadPinned、分配栈/线程分析，以及多目标并排比较。按真实事件和支持范围逐项验证，不把局部数据称为完整覆盖。

这些优先级来自本次实现与流程检查，是产品判断；没有开展新的用户访谈或声称已证明切换率。现有数据也不足以给插件标注“完美”或全平台稳定。
