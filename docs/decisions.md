# 首版决策与实现边界

初始调研日期：2026-09-23；本页更新：2026-09-28。开发名 JVM Beacon，当前首发候选版本 1.0.0-rc.1；名称、plugin ID、发布者及正式许可证尚未完成公开发布审查。以下按阶段保留决策；已完成与下一步以最新条目和验证记录为准。

## 0.6.1：先处理连接与趋势反馈

用户报告默认 `run-fixture.ps1` 偶尔连不上、Trend 不更新与 Stale。该命令没有运行时限；不能把问题归因于定时退出。代码检查确认容量拒绝曾错误释放健康连接；实际实验确认旧交互 fixture 收到空行即退出。两者已修正，但缺少用户当时的错误码，尚不能确定其个案根因。

连接等待从普通请求分离为 20 秒，并展示 Attach/代理/JMX/身份/首采阶段；仍然受原有线程、许可、超时和迟到清理约束。普通请求保持 8 秒。网络容量不足保留会话并暂停自动采样，明确提示后由用户恢复；没有自动重试写操作或自动重连。

Trend 的下拉框只切换指标，不隐式开始采样；新增明确的 Start live trend、模式、最后样本时间/年龄和有界点数。绘图使用纯数据模型，统一可读单位，单点与恒值居中，缺失/长间隔/倒退时间断线；可悬停查看精确原值与采集窗口。图表标题适应可用高度，避免说明挤掉绘图区。默认 fixture 忽略空行，只在 quit、标准输入关闭或终端退出时结束，并输出原因。

本补丁优先恢复日常工作流可信度；锁关系、JFR 与持久连接工作区继续保留在路线图，不用新菜单掩盖稳定性问题。实际验证范围见 [validation.md](validation.md)。

## 产品判断

见 [可追溯调研](research.md)。成熟工具的 CPU/内存分析、JFR 事件解释不值得首版重做。先解决开发者频繁切出 IDEA 才能完成的 JMX 查看与现场记录：选择本地进程或输入远程地址 → 确认身份 → 查看指标 → 搜索/收藏 MBean、读取复杂属性、受控写入和操作 → 平台线程快照 → 带时窗和备注保存、离线重开/比较。

切换理由是减少日常操作步骤，并把数据的范围和状态解释清楚；这仍需用户试用验证，不是已有市场结论。首版不做健康分、自动根因判断或未采集历史恢复。

研究文档保留 2026-09-23 的初始建议；实现时已将收藏、跨现场文本比较和受限源码导航提前纳入预览。0.3.0 加入单个数值属性追踪；运行配置关联仍属后续范围。当前完成程度以本页及验证记录为准。

## 连接与安全边界

- 进程列表仅枚举；连接使用 Attach，需要启动目标管理代理时由用户明确允许。依赖同用户权限、目标 Attach 能力/策略，可能受容器及临时目录限制。列表不是“所有 JVM”。
- 远程输入 hostname:port、[IPv6]:port 或完整 JMX/RMI URL。注册表 TLS 与 server stub 的连接 TLS 是两个层面；使用 JBR 信任配置，不植入信任所有证书的代码。首版没有每连接独立 truststore/SSH。
- 默认观察模式是客户端防误触。服务端授权仍然决定读写许可；读取 MBean getter 也可能有成本或副作用。
- 属性写入、操作、通知订阅、启用本地代理均解释影响。操作按精确签名调用；不对任意 Java 对象做猜测式转换。修改超时不由应用自动重试。JDK provider 自身可能执行有限连接恢复，见核心说明。
- 不上传任何运行数据，不带遥测、云账号或 AI 依赖。快照不收凭据、连接 URL、完整命令行、系统属性或任意 MBean 值；线程名、栈、目标身份和备注仍可能敏感，并非完全匿名。

能力依据：[JDK25 JMX 管理指南](https://docs.oracle.com/en/java/javase/25/management/monitoring-and-management-using-jmx-technology.html)、[ThreadMXBean](https://docs.oracle.com/en/java/javase/25/docs/api/java.management/java/lang/management/ThreadMXBean.html)。JDK25 文档用于核验边界，实测版本另列。

## 生命周期与预算

- 网络/Attach/磁盘/PasswordSafe 不在 EDT。每视图最多一个在途操作；全应用网络/Attach 池最多 4 线程，本地文件/PasswordSafe I/O 池最多 2 线程，分别无任务队列。连接 20 秒、普通请求 8 秒用户可见截止时间，截止不等于底层调用停止。
- 取消、断连、项目关闭后清除 UI 回调。连接前预留许可：全应用最多 16 个处于连接中、活动或关闭中的连接。每个连接只入清理队列一次，关闭返回后才释放许可；最多 2 个清理线程和 16 个队列位置，为已接纳连接保留关闭容量。迟到结果也持有许可。插件释放时不丢弃已排队关闭任务；底层永久阻塞仍可能让有界线程/资源存活到 IDE 退出，不能承诺动态卸载彻底回收。
- 采样由用户开启，2 秒间隔、不重叠，最多保留 120 点；通知最多 200 条；MBean 列表、格式化结果、线程及栈深均有限制并标识截断。工作线程空闲后退出。
- 单次卡住的标准 RMI/Attach 不能由 Java 中断强制终止。隔离额度耗尽时明确停用，不能宣传绝对无资源残留。
- 网络池与本地 I/O 池已隔离：四个网络调用永久阻塞不会占用离线现场读取、保存、比较或 PasswordSafe 的执行名额；本地池本身耗尽时仍明确拒绝，不增加排队任务。
- 预算目标（尚非测量结论）：空闲不采集、采样无重叠；健康 loopback 平均采集耗时小于 100 ms、p95 小于 250 ms；插件有界历史小于 20 MiB。历史独立基线仅评估时延，不证明 IDE 内存预算达成；长时间 IDE CPU/堆开销需独立基线对照，见 [验证记录](validation.md)。

独立 JVM 资源测量于 **2026-09-24** 用当前核心重复 180 秒，原始记录与 2026-09-23 基线分别保留，见 [资源观察](soak-validation.md)；均不代表整个 IDEA 的性能结论。

- 平台线程按名称/ID/状态过滤已采集数据，显示匹配数/采集数，空结果不声称目标无线程。纯核心 `ThreadComparison` 不调用目标 JVM：只有身份完整一致、双方线程采集有效时才比较同 ID 候选的名称、状态、已保存栈字段和锁名称信息。
- 比较每侧最多 512 条、每栈 64 帧、最多 200 条差异及 32,768 字符结果；保留双方窗口、截断和时间顺序提示。新增观察/未再观察不是创建/结束结论，ID 可复用，未变的栈不是持续阻塞或死锁证据。现有现场格式不增加未采集历史。

## 阅读与源码定位

- MBean 过滤保留仍匹配的选择，不因列表重建重复读取远程属性；无选择或空结果时清空详情。读取和操作显示后台实际采集窗口，不使用 EDT 回调到达时间冒充采集时间。
- 现场比较使用独立固定标签，保留比较时的输入和结果，实时采样不覆盖正在阅读的比较。导出范围仍只有一次指标、一次平台线程及备注，不包含趋势或任意 MBean 历史。
- 源码查找优先匹配精确二进制名称和真实成员类关系，保留标识符中合法的 `$`；通过 navigation element 查找依赖/JDK 的附加源码 mirror。多个候选仍拒绝自动选择。
- 匿名/局部类仅在编号形式合理、外层类可精确解析、源码文件和行范围吻合时提供候选。用户明确确认后才打开候选行；不宣称匿名编号或运行字节码与源码版本一致。精确匹配路径也保留版本核对提示。
- 0.1.3 修复单参数对话框过高，已在本次窗口复测零/单/双参数和数组输入布局。0.1.4 修复目标操作异常被误归输入错误（GUI-02）：优先识别 MBean 异常包装；单元与实际 GUI 回归均已观察到目标失败分类，连接保持，不自动重试。

## 0.3.0：简写远程地址与属性追踪

0.3.0 的连接入口接受 `hostname:port`、IPv4、`[IPv6]:port` 及完整 JMX/RMI URL，提供即时端点预览和端口校验。凭据键使用规范化后的端点及用户名；保留完整 URL 的自定义 binding，不做 DNS 推断或自动 TLS 降级。

数值追踪从 Attributes 的实际选择开始，独立 Watch 页提供趋势、精确值、窗口、暂停/恢复与清空。单个 getter、最多 120 点（含间断标记），仅在工作台可见且无在途请求时按 2 秒调度；与标准指标共用已有调度和受限执行器。失败保留原因并暂停；断开保留 STALE，重连或离线打开清除旧追踪。暂停、清空与替换追踪后丢弃迟到值，不声称取消终止远程 getter。图表使用近似 double，表保留受支持数值的精确字符串，未知单位明确显示；拒绝任意 Number 子类，限制巨大数值显示。不纳入 `.jvmb` 导出，现场范围维持明确边界。

## 0.5.0：多个连接的原生标签页

用户需要同时连接多个 JVM 并切换。0.4.0 每项目只有一个工作台；0.5.0 改用 IntelliJ ToolWindow 的 Content 标签，每页独立 `BeaconPanel`、`SessionRunner` 和目标状态，复用全局有界执行器。标题栏 + / 工作台内 Alt+Insert 新建页，Replace JVM 只作用于当前页；数字页编号避免相同 runtimeName 无法区分。关闭 Content 通过 disposer 取消 UI 回调、停止定时器并释放连接/监听器；最后一页关闭后延迟建立空白页，项目或 ContentManager 释放时不重建。

依据：[官方 Tool Windows / Contents 与 Closing Tabs](https://plugins.jetbrains.com/docs/intellij/tool-windows.html)，查询 2026-09-24，官方文档（页面标注 2026-03-25）；251 本地 SDK 编译和 Verifier 另行核对。使用原生 tab/关闭按钮，不搬运界面资源，也不新增一套自绘分隔和切页样式。

每项目上限 8 页；网络/连接/本地 I/O 上限保持全应用共享。只对可见页调度 Auto/Watch，隐藏页保留连接、历史与有界通知。切换不刷新 MBean getter；收藏修改先读最新应用集合，切回时刷新列表但不重复读取属性。离线现场也可单独占页，不承诺跨目标联合图表、后台连续采集或重启恢复。关闭页丢弃未保存数据；目标已开始的操作可能继续。

新增自动检查覆盖两个认证 loopback JVM 的属性和通知隔离、一端关闭/退出另一端继续，以及一个 SessionRunner 释放时迟到连接清理而另一会话正常回调。具体 GUI 和最终包记录见验证文档；可照做的步骤集中在 [testing.md](testing.md)。

## 0.6.0：Hot threads 与下一阶段诊断路线

先实现可即时使用的平台线程 CPU 增量：两次批量计数、实际窗口、数值排名、单核占用短条、末次栈和现有源码导航，缩短“哪个线程值得进一步看”的路径。仍不能证明热点方法或根因，此差异化价值尚未做外部用户验证。

只读 JDK 扩展 ThreadMXBean 的批量接口，最多 512 个排序后的基线 ID；不支持时明确返回，不发数百个逐线程远程调用。受控后台任务等 1 秒，以客户端单调时钟记录两次 counter call 中点间隔及读耗时，估算单核百分比；超过 100% 不裁掉原始值，只限制短条宽度并解释时序误差。末次 metadata 与 CPU 读取不是原子快照。监控未启用不改设置；身份变化、计数不可得/降低不用零代替。ID 复用或期间监控重置不能完全排除。

每连接页只留最后一个不可变报告，筛选/数值排序/展开栈不读取目标；沿用 SessionRunner 的超时、取消、迟到丢弃及全局预算。断开标记 Stale，换目标及离线打开时清空。复制带身份、计时和边界的报告，明确不脱敏；未扩展 .jvmb 格式。没有新增依赖或复用竞品代码/资源。

仍未实现且值得推进的能力：

| 优先级 | 能力 | 任务价值与前置验证 |
| --- | --- | --- |
| 下一阶段 | 锁等待关系图、线程差异结构化视图 | 沿真实 owner 关系查看等待链；先增加采集字段及有时限锁竞争 fixture，不把一帧等待判成死锁 |
| 下一阶段 | JFR 有界录制、下载及事件分析 | 查 CPU 方法、分配、GC/锁事件的时间关系；先核对权限、配置和开销，明确启停影响，成熟引擎复用前查许可证 |
| 随后 | 多指标/多 JVM 同屏比较、可保存诊断会话 | 关联 heap/GC/线程/业务 MBean；先定义时钟偏移、缺失、采集间隔及导出预算 |
| 随后 | 连接工作区、运行配置关联与重启提示 | 保存别名/端点、凭据保持 PasswordSafe；重启后核对身份，不恢复写入或自动猜目标 |
| 按场景验证 | HikariCP/Tomcat 等组件面板 | 以已暴露 MBeans 展示容量与用量，区分供应商/版本/权限，不凭名称猜语义 |
| 按场景验证 | SSH、Jolokia、容器发现、虚拟线程采集 | 解决访问路径和覆盖边界，独立验证协议/权限及环境矩阵 |

以真实证据、快速定位和原生键盘操作实现极客感；未实现能力不摆空按钮，不以装饰动画或虚构健康分替代诊断。研究依据、自动与 GUI 结果分别见 research/validation/gui-validation。

## 0.6.1 后路线复核（2026-09-24）

这是根据当前代码、验证缺口和用户反馈形成的后续建议，不是已实现功能或固定发布承诺。此为 0.6.1 时的代码状态；0.7.0 落实范围见文末。

0.6.1 代码核对：`JmxClient.ThreadRecord` 保存锁名与 owner 名称，没有 owner ID 或持有锁明细；现有 JVM 死锁查询/标记不能称为完整等待链分析。`BeaconSettings` 仅持久化收藏，不包含连接配置。`SnapshotStore` v1 只有一次指标、一次线程快照及备注；Hot threads、趋势、Watch 与复杂 MBean 结果没有被保存。Operations 已可调用暴露的方法，后续是改善复用与结果比较，不是重新开发调用入口。

下一个里程碑的验收场景：启动有时限、可清理的锁竞争 fixture → 连接 → 捕获平台线程 → 从等待线程定位 owner 和栈 → 释放竞争后再次捕获 → 结构化比较 → 保存/离线重开，关系与窗口保持一致。包含未知 owner、线程消失、重复线程名、截断、权限拒绝与目标退出测试。首版优先清晰的等待链列表及选中链路视图，不绘制不可读的全量网络图；不承诺仅凭两帧证明持续阻塞。

其他高价值候选（全部未实现）：

- **MBean 工作流提速**：操作收藏/快捷入口、签名明确的参数模板、属性前后差异、结构结果 CSV/JSON、通知过滤与时间线；调用仍逐次确认，参数不默认持久化。
- **组件视图**：HikariCP/Tomcat/日志级别等已暴露 MBean 的任务面板，先核对实现版本、单位及权限。不把对象名称匹配当作功能兼容保证。
- **证据触发器**：用户明确启用“阈值持续多次满足后保存一次现场/录制”，有冷却、次数、磁盘和目标负担限制；不默认触发任意业务方法或上传数据。
- **多 JVM 对比**：同一指标并排、身份/启动时间明确、采集错位可见，作为现有多连接标签的扩展。
- **远程环境**：每连接证书配置体验、SSH、Jolokia、容器访问指引与发现分别验证；SSH 一个端口转发不保证 RMI stub 可达。
- **虚拟线程诊断**：独立的 JDK 能力探测、线程转储导入和 JFR 事件视图；不沿用 ThreadMXBean 平台线程覆盖声明，不保证跨 JDK 事件语义相同。
- **IDE 效率**：Run/Debug 入口、命令搜索/快捷键、可固定数值卡片和诊断标注。先形成可用流程，再增加视觉反馈。

产品判断：锁链能补上“卡在哪里”，连接工作区减少每天重复配置，时间线/现场解决“发生过什么”，JFR 才进一步回答“哪些采样栈或事件值得看”。完整堆转储分析器、任意表达式执行和自动根因结论暂不自研；必要时有明确入口交接成熟工具。以上优先级是本项目判断，不宣称经过外部用户研究验证。

## 0.7.0 实施范围（2026-09-24）

本轮落实路线的第一项：Lock chains、固定 A/B 结构表、锁关系现场保存/重开。原线程批量读取同时保留 getLockOwnerId，不增加逐线程网络调用，也不启用 contention monitoring。null 表示旧现场未采集、-1 表示查询未报告 owner，正 ID 才连边。路径最多 64 成员，只处理已有 512 条记录；图中的环是非原子观察，独立的 JVM 死锁查询仍单独报告。

交互使用线程页的 Snapshot / Lock chains / Compare / Hot threads 原生子页。选链成员阅读已有栈，复用源码导航；搜索、排序不查目标。每页保留一个基线和固定比较，清空、换目标或打开文件后用 generation 隔离迟到计算。文件比较明确文件 A 与选择时 B，线程表与现有文本比较同时生成。比较计数与最多 200 条明细的限制分开。

现场写 v2、读 v1/v2；v2 增加 owner ID 的 presence 与值。旧文件不补造关系，旧读器不承诺兼容 v2。仍是一次指标与一次线程窗口，不保存比较报告、Hot threads、趋势或任意 MBean；要离线重算比较，分别保存 A/B。未添加持有锁清单/所有同步器监控；等待关系不能称为全量锁分析。

测试 fixture 通过两个显式 MBean 操作启动/释放三段竞争，单组 3 个 daemon 平台线程，总时限 1–120 秒，重复启动先释放并 join 上一组。提前释放后保留至原截止时间，以验证相同 ID 的不同观察；finally 清理。不默认制造负载或永久死锁。

实际测得的一轮 125% GUI 发现长说明挤掉成员列表，随后缩减常驻说明，把完整采集/比较证据放入原生详情窗口并调整分隔比例。最终验收与限制见 validation/gui-validation，不能从设计调整本身推定通过。

## 0.8.0 连接工作区（2026-09-24）

本阶段减少每天重复输入远程配置：在现有原生连接对话框中加入 Saved connections，支持别名、字符串分组、搜索与最近成功项。没有另建全局复杂树或自动发现网络；最近项是成功用过的已保存配置，不是所有连接活动审计。保存 40 项、最近 10 项；本地 PID 只存在当前页内存，不在下次启动时猜测复用。

使用应用级 PersistentStateComponent 与 RoamingType.DISABLED 保存非密码元数据；PasswordSafe 沿用原规范端点+用户名作用域。UI 内仅访问有界内存快照，框架负责设置落盘；PasswordSafe 仍走两个线程的本地 I/O 池。地址仅允许可审阅的 JNDI/RMI 形式持久化，拒绝 userinfo/query/fragment/opaque stub；不声称能自动识别用户填入任意字段的所有秘密。

显式重连是每页一次新的连接尝试，复用现有 20 秒连接期限、全局执行器和资源许可。恢复只读、关闭自动采样、清空旧数据序列与比较；不重放写入、操作、订阅或 agent-start 许可。密码读取返回值可在迟到/取消时擦除；没有密码时打开预填表单，不无限提示或自动重试。保存配置被另一页删除/改端点后，迟到连接只影响自己的会话，不覆盖新的配置；别名变更保留。

目标变化基于 runtime name/start time/VM name/version 的报告值，缺失字段不视为相同。连接成功的初始样本开始新窗口；不把相同身份当作服务器认证。现阶段没有进程重启的 Run/Debug 关联、启动恢复活动标签、自动重连、每连接 truststore 或 SSH。

实测候选界面发现重连提示挤压趋势图，已把目标身份和说明扩为顶部整行。验收与最终字节对应关系见验证文档。无新增依赖及竞品资源复用。

下一阶段优先 **多指标时间线与可保存采集区间**：统一 CPU/heap/GC/线程时间轴、标记缺失和采样空档、选择区间比较、保存已有历史且限制磁盘/内存。之后再做有界 JFR 开始/停止/取回与成熟分析工具衔接，明确记录权限、目标开销和虚拟线程覆盖；不把连接工作区的完成称为整个愿景完成。

## 0.9.0 时间线决策（2026-09-28）

交付四轨 Signal timeline：CPU recent load、heap used、GC cumulative collection time、live platform threads。统一已有样本时间轴与游标；不增加 sampler、网络任务或监控权限。沿用 120 点短窗口，冻结视图时最多额外保留 120 点不可变引用；真实采样继续与否由现有 Auto 开关决定。冻结后按采集序号选择范围，避免滚动缓冲导致保存区间漂移。窄窗口轨道滚动；方向键/数字微调可代替鼠标悬停。

采用 `.jvmb` v3 扩展现有安全纯数据格式，读取 v1/v2/v3。sample 是最后一次采集点，history.count 表示它之前的样本数（0–119），全部保留窗口、单位和不可用原因；线程仍为独立可缺失采集。Save snapshot 保存当前保留历史及线程；Save interval 只存选中指标、身份和备注，防止暗示线程同时采集。仍限 5 MiB，写入前验证，临时文件原子替换优先，不恢复已丢弃或未采集历史。

GC 不派生暂停占比，CPU 不声称两秒平均。区间仅比较端点：任何缺失/不同单位/倒序或重叠时窗抑制差值；GC 已观察到回退时抑制差值；跨采样空档仅标端点变化，不推算区间连续行为。统一时间轴帮助发现同时出现的变化，是待用户验证的工作流收益，不证明因果。

接下来优先做有界 JFR 开始/停止/取回与 JMC 分析衔接；先验证服务端权限、目标开销、文件大小/时长边界和取消语义，不自动开启录制。之后补 Run/Debug 目标关联、更多组件专用视图和更广的真实网络/IDE 验收。

## 0.10.0：有界 JFR 与离线事件库存（2026-09-28）

首版只管理每个 JMX 连接创建的一个 recording，显式探测目标 default/profile 预设；不列出或接管其他工具的录制。Read-only 禁止开始/停止/释放；下载需要打开目标流，实际仍可能要求服务端控制权限。确认包含目标、资源与隐私影响及断连清理政策。

启动顺序固定为 newRecording → 保存 ID → 设置 5–120 s duration/maxAge、disk=true、32 MiB maxSize、dumpOnExit=false → 配置预设 → start。发生失败不重试、不另建录制；已知 ID 用于后续刷新/清理。退出会话先设置非阻塞取消标记，既有连接清理队列负责释放；取消后返回的 ID 不再启动，网络断开仍无法保证服务端已清理。无法取回 ID 的失败不宣称成功回滚，目标保留录制需管理员检查。

下载只用自有、已停止 ID 的 JMX stream，每块 64 KiB，总量 64 MiB，45 秒循环预算/60 秒界面截止。临时文件只在完整读取并关闭流后提交，不覆盖旧文件；超限/取消移除未完成文件，底层无限阻塞仍只能由既有线程/连接预算约束。文件与网络调用均不在 EDT；普通请求依然 8 秒，JFR 冷启动 20 秒。读取/失败后需显式刷新，不为 JFR 另开轮询器。

离线用 JDK RecordingFile 形成不可变库存，事件计数可搜索排序；详细报告保留实际事件窗口和限制，不保存事件对象图。限制 64 MiB 文件、200k events、256 types、5 秒扫描检查，单次 JDK 解析不视为硬隔离。原 .jfr 不脱敏、不上传、不放入 .jvmb。现阶段交接 JMC 是复制路径并手动打开；尚未集成外部启动器或自研调用树/火焰图。

下一阶段优先用已有 .jfr 做有界采样栈聚合、可解释调用树/火焰图，再扩展 GC/分配/锁事件视图和 Run/Debug 目标关联。生产网络、更多目标 JDK、长时开销和动态卸载仍需单独验证，不将本次小样本录制称为性能验收。

## 0.11.0：采样路径分析（2026-09-28）

在同一次有界文件扫描内复制 ExecutionSample/NativeMethodSample，避免为库存和栈各做一次文件读取。UI 不保留 RecordedEvent/Frame/Thread 对象；总量限定 20k 样本、200k 帧引用、128 帧/栈、256 线程、8192 不同帧、2 Mi 字符帧元数据，名称/描述符各 512 字符。达到预算后继续既有库存扫描并记录遗漏数；不是均匀抽样，也不保证保留按时间最早的样本。单次 JDK 解析仍无硬隔离。

聚合复用 LOCAL_IO 与 SessionRunner，kind/线程筛选显式 Apply，不新增池、计时器或远程调用。树上限 8192 节点，整条路径不够空间就省略并计数，避免把被剪掉的子帧伪造成父帧 self。类 ID、descriptor、行号参与路径键，递归保留层次。截断栈加未知更早帧根；分母是当前筛选后实际表示的样本。没有 CPU 时间、方法调用次数或全线程覆盖推断，也不混合 Java/native 样本。

火焰图采用根在上方的可缩放布局；克制的主题色只是方法分类，不是健康程度。Highlight 只高亮，不改变计数。极窄帧可用 Call tree 键盘选择，再 Zoom selected；详情占比仍相对筛选后的整棵树，非缩放子树。每页只保留一份文件分析，换文件/目标或清空以 generation 丢弃迟到聚合。源码定位不猜 .java 文件名，需精确类/descriptor/方法行匹配、唯一候选并显式确认，仍不验证运行字节码版本或 loader→IDE 依赖映射。

实际 125% GUI 初次验收发现录制状态和帧详情挤掉图表，随后加入可收起的 Capture controls，载入文件后收起；收起不停止 recording，紧凑状态仍可见。帧详情压缩为可滚动两行区域。新 UI 最终验收另记，不用修复前截图充作通过证据。

下一步优先 **GC 事件时间线与分配采样分析**：将停顿事件和累计 GC MXBean 指标分开、保留事件时窗/阈值/缺失，研究 allocation weight 语义后再聚合，不把样本事件数当字节数。之后是 JFR 锁事件关联、时间范围选择和 Run/Debug 目标关联。更多 IDE/JDK、真实 WAN、长时开销、无障碍仍需专项验证。

## 0.12.0：GC 时间线与分配压力

库存、采样栈与内存分析同次扫描，不新增网络请求、定时器或线程池。额外保留最多 4,096 个 GC 事件和 2,048 个分配类，名称最多 512 字符；不可变结果交给 UI。两种 GC 事件共用预算，不保证文件顺序等于时间顺序；显示前按时间排序。预算满后记录遗漏，不称为均匀采样。

GC 双轨分别展示 GarbageCollection / GCPhasePause，表格和纳秒详情是精确读数入口；未求暂停百分比，也不跨事件猜测根因。Allocation 只聚合带 bytes 注解且非负的 weight，以 BigInteger 避免溢出，键是记录内 class ID + 名称；已保留类继续累加，新类超限计遗漏。份额分母固定所有保留权重，搜索仅影响可见项，零总权重不显示伪造的百分比。复制所选证据包含覆盖报告。

暂无 allocation 栈/线程归因、堆前后关联、时间范围过滤或泄漏诊断。下一步优先 **JFR 锁等待事件分析（JavaMonitorEnter / ThreadPark 的不同语义、阈值与栈）**，之后做统一时间范围筛选和 Run/Debug 目标关联；性能与广泛兼容性另行验收。

## 0.13.0：等待事件工作流

同次 JFR 扫描复制 JavaMonitorEnter、JavaMonitorWait、ThreadPark，不新增远程请求或线程池。每页最多 4096 events、65536 frame refs、64 帧/栈、4096 唯一帧，事件/帧元数据各 1 Mi 字符、单名称512；栈预算不足保留事件时长，区分未录/遗漏/截断。class ID+descriptor+line 复用现有保守源代码候选协议。对象地址不进模型；previousOwner/notifier 不推断当前持锁关系。

热点按类型、类、叶帧分组；BigInteger 累加纳秒，避免并发等待和大值溢出造成假指标，不计算墙钟百分比。筛选在 LOCAL_IO，Apply 明确提交，generation 丢弃换文件后的迟到结果；UI 表格批量替换，热点下钻事件、详情使用原生对话框，保留主表空间。详情可查看原始窗口和栈、复制覆盖，需用户选有行号的帧才导航。

第一次测试把虚拟线程 park 必有 ThreadPark 当作假设，真实文件推翻了该假设。产品遵从录制内容，报告覆盖不足；自定义 probe 只用于验证 virtual 元数据，不补造标准事件。下一阶段优先统一 JFR 时间区间筛选与跨视图关联，其后 Run/Debug 目标关联；VirtualThreadPinned 与分配栈分析按独立语义扩展。仍未做大文件/长时/所有 JDK 或 IDE 的全面性能验收。

## 0.14.0：统一分析时间区间（2026-09-28）

分配在 0.12 按类汇总，原汇总无法可靠逆推某一时间段的 weight。因此显式改范围时复用 LOCAL_IO/SessionRunner 重扫原文件，先以 UTC [from, until) 筛选，再同时建立库存、栈、内存和等待结果。瞬时事件按时点，持续事件按正相交；完整时长/周期暂停字段绝不裁剪。GC 仅裁剪视觉标记，不推出区间暂停率。范围内 allocation 重新累计、份额分母是所选范围的保留权重。

所有范围共用文件扫描 64 MiB/200k/5 秒软预算；200k 包含被区间排除的事件，分析保留预算在过滤后计算。不会假设文件已排序而提前停止，也不承诺完整范围覆盖。只保留当前结果，更新时暂时并存旧结果与一个有界候选；成功后整批替换，失败保留全部旧范围与 Update failed，generation 阻止迟到文件响应。size/mtime/fileKey 扫描前后核对，只防常规变化，不是内容认证。无需新增线程池、网络调用或配置文件。

Time range 使用相对已扫描文件起点的精确秒数，范围状态持续可见；GC/等待详情可一键聚焦前后最多 100 ms。已有应用筛选保留，选择/缩放清除，未提交草稿不冒充已应用条件。Focus 只提供同窗查看，不推断因果。下阶段优先 Run/Debug 目标关联；Pinned/分配栈、更广兼容与性能验收仍未完成。

## 0.15.0：先让 MBean 日常操作可控（2026-09-28）

选中 MBean 仅调用 getMBeanInfo；定义与操作可先使用。Read value / Enter 是单项 getter 请求，名称/类型筛选和选择均不远程读取。属性表与值、操作表与结果使用左右细分隔，缩小顶部说明；Metadata 提供完整有界说明、来源/窗口/截断。方法按名称/签名本地过滤，保留同一操作的结果。

每对象最多保留最近 8 项读取（每项沿用 512 节点/32768 结构字符，独立文本也有界）；淘汰明确说明，不自动回读。元数据最多 1000 属性/512 操作/32 参数，名字/类型超长条目省略计数，描述共享 256 Ki 字符，剥离 descriptor。仍无法约束 RMI 反序列化阶段，限可信目标；不宣称 metadata 本身没有目标开销。

写入确认、只读保护、超时不重试不变；成功仅回读原属性，write-only 只显示返回成功。切对象/Reload 清缓存、断连结束 pending 并丢迟到响应，不用最后选中行替代原写入目标。值有各自 UTC 窗口；不纳入 .jvmb、不假装多项原子快照。未增加 Read all 或自动展开读取，避免恢复旧问题。

下一阶段按此前顺序推进 **Run/Debug 精确目标关联**（先验证 PID 可用边界，不凭名称猜进程），并安排凭据/资源专项；后续才是持久诊断工作空间、VirtualThreadPinned、allocation 栈。本阶段不把这些路线项称作完成。
